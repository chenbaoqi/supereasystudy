# ADR-014：AI 辅导页（页面契约与上下文传递方式）

- 状态：已采纳并实施（2026-09-13）
- 决策人：Owner（2026-09-13「颜色改好做AI辅助」）
- 需求依据：第三十八章（AI 学习助手：换方式解释 / 降低难度 / 举例 / 只提示一步 / 为什么 /
  类似题 / 错因 / 建议 / 问答）、第三十九章（**AI 只解释，标准答案由题库与程序决定**）
- 影响范围：新增 `pages/ai-tutor/`、`services/aiTutorActions.ts`、`tests/aiTutorActions.test.ts`；
  改动 `pages/mine`、`pages/study-detail`、`app.json`

---

## 1. 背景：后端早就通了，用户却够不着

排查发现：`cloud/functions/aiTutor`（DeepSeek，2026-09-13 已联调通过，单次约 1.45s）、
`services/aiTutorService`、`repositories/aiTutorRepository`、`core/ai.ts` 契约、12 个单测**全都齐了**，
但**全项目没有任何页面引用 aiTutorService** —— 功能对用户完全不可见。
`FEATURE_FLAGS.aiTutor = true` 也一直只是 service 内部的守卫，不代表有入口。

本 ADR 落地的是**界面层**，不改任何 AI 侧协议。

## 2. 决策一：上下文走 URL 短参数，本页不读数据库

`AiTutorContext` 要求 7 项上下文（学段 / 年级 / 学科 / 知识点 / 题干 / 学生答案 / 正确答案）。

**做法**：由**进入本页的上游页面**把上下文拼进 URL query，AI 页自己不碰数据库。

**为什么不查库**：

1. 上下文本来就在上游手里——学习详情页有当前知识点、测试页有题干与选项，再查一次是多余 IO。
2. **查库会查错**：学习详情页允许「上一条」回看，此时 `learning_records.currentKnowledgeId`
   已经不是眼前这张卡了。用记录去反查知识点，AI 会拿到用户没在看的那一条。
3. 本页零 Repository 依赖 → AI 不可用时页面**自身**依然完整（只降级文案，不降级界面）。

**代价**（已知并接受）：

- URL 只能承载短文本：学习详情页只传知识点名，不传释义/例句。
- 参数需 `encodeURIComponent` 编码，页面侧统一 `decodeURIComponent`。

**补充（2026-09-13 晚，同一天）**：题干、选项、三级提示这类**长文本与数组**改走
`services/aiTutorHandoff.ts` 的内存交接，不再硬塞 URL —— 详见 §7。
URL 参数降为**兜底通道**：交接丢失（小程序被回收）时页面照旧可用，只是提示退化为通用文案。

## 3. 决策二：「场景 → 快捷按钮」抽成可单测的纯函数

`services/aiTutorActions.ts` 定义三种场景与各自的按钮集：

| 场景        | 触发条件       | 典型入口            | 快捷按钮                                                                |
| ----------- | -------------- | ------------------- | ----------------------------------------------------------------------- |
| `question`  | 带题干进来     | 测试/练习答错后     | 我没看懂 / 再简单一点 / 只提示一步 / 为什么 / 错因在哪 / 给我一道类似题 |
| `knowledge` | 只带知识点进来 | 学习详情页「问 AI」 | 我没看懂 / 再简单一点 / 举个例子 / 只提示一步 / 为什么 / 学习建议       |
| `free`      | 什么都不带     | 我的 → AI 辅导      | 学习建议（其余靠输入框）                                                |

抽出来的理由：这是**产品规则**（谁能看到哪些按钮、开场白说什么），不是样式细节；
放 wxml 里就只能靠肉眼验证。`tests/aiTutorActions.test.ts`（11 个用例）守住：
场景判定、按钮不丢（文案漏配会静默丢按钮）、按钮不重复、`status`/`qa` 不进快捷栏。

## 4. 决策三：降级必须「可辨认」

第三十九章要求 AI 只解释不判分。据此在 UI 上做了三件事：

1. **AI 不可用时气泡下方标注「程序化提示（AI 暂不可用）」** ——
   绝不把兜底文案冒充成 AI 说的。
2. 页面顶部在 AI 未配置/连不上时显示提示条，但**不阻挡操作**（照常能点、照常有兜底）。
3. 底部常驻免责说明：**「内容由 AI 生成，仅供参考；标准答案以题库与老师讲解为准」**
   （同时满足生成式内容标识的合规预期）。

## 5. 决策四：入口按开关渲染，且只在有上下文价值的地方开

- 「我的」页：`FEATURE_FLAGS.aiTutor` 为假时**整行不渲染**（不是置灰），带当前学科与年级。
- 学习详情页：`✨ 问 AI` 按钮，带知识点名 + 学科 + 年级。
- 测试页：**已接**（见 §7）。答错后才出现「✨ 问 AI 为什么」，答对会自动进下一题，
  弹一下按钮反而晃眼。

## 6. 后果

**正面**：AI 辅导从「后端能用、用户够不着」变为可用；两个入口覆盖「自由问答」与「知识点求助」；
按钮可见性有单测；降级可辨认。

## 7. 补充决策（2026-09-13 晚）：答错场景与内存交接

### 7.1 为什么必须另开一条通道

测试页的 `QuizQuestion`（`ChoiceQuestion`）**没有 `hints` 字段** —— 分级提示只存在于
`core/question.ts` 的 `Question`（题库结构），测试页用不到。而 `aiTutorService` 的降级兜底
恰恰是吃 hints 的。所以「答错 → 问 AI」不是接个按钮，而是要把两套结构接起来。

中文经 `encodeURIComponent` 后每字 9 字符，题干 + 4 选项 + 2 答案 + 3 条提示轻松上千字符，
且选项是数组、塞 URL 要自己定分隔符再拆回来。故新增：

- `services/aiTutorHandoff.ts` —— 内存单例，`set` / `take`（取走即焚）/ `clear`。
  **一次性**：不落 storage，否则下次直接进 AI 页会读到上一次的题。
- `services/aiTutorQuestion.ts` —— 纯函数：`stemOf`（听力题把被朗读的词写进题干，
  AI 听不到音频）、`hintsFor`（从知识点数据反推三级提示）、`buildQuestionHandoff`、
  `mergeContext`（交接里显式 `undefined` 不得抹掉 URL 参数）、`contextMetaLines`。

### 7.2 三级提示的来源与两个踩坑

`hintsFor` 按 轻提示 → 分步 → 完整讲解 三级产出，与 `aiTutorService.fallbackText`
的取用下标一一对应（`hint`/`simplify`→[0]，`explain`→[1]，`example`/`why`→[2]）。

写单测时抓到两个**我自己写出来的产品 bug**，一并修掉：

1. 语法题的轻提示只说「回想这个语法点：表示经常发生的动作」——**没点名是哪个语法点**。
   已改为带上 `knowledge.word`：「回想「一般现在时」这个语法点：…」。
2. 无知识点兜底的第 2 级提示原本藏着答案不给。但答错后正确选项**已经在屏幕上标绿**，
   学生早就看见了，提示再装糊涂没有意义 —— 已改为第 2 级直接点明正确答案，
   第 1 级仍保留「只提示一步」的梯度。

### 7.3 契约与云函数同步改动

- `core/ai.ts` 的 `AiTutorContext` 新增 `options?: readonly string[]`。
  没有选项，AI 讲不清「为什么这个对、那个错」。
- 云函数 `buildUserMessage` 渲染选项行（A./B./C.），并在学生答案 ≠ 正确答案时
  显式追加「学生答错了：请围绕两者差异讲解，不要复述整道题」。
- 云函数 system prompt **按学科换角色**（原来写死「中小学数学辅导老师」，
  英语题问「为什么选这个单词」也会被当数学题讲）。
- `ai-tutor` 页维护 `hintHistory`（已给过的提示），连点两次「只提示一步」不会得到同一句话。

### 7.4 学科去默认（2026-09-13，Owner 反馈「进去默认是数学？这个就不用默认了吧」）

`数学` 不是写死的，是 `resolveSubjectOfSemester(当前教材册次)` 反查出来的 ——
用户教材偏好停在数学，就被带进了 AI 页顶部。但自由问答**没有题目也没有知识点**，
此时预设学科等于替学生决定"你现在问的是数学"。

**规则（写死在页面里）**：

| 场景        | 学科来源           | 用户能否改 |
| ----------- | ------------------ | ---------- |
| `question`  | 题目所属册次反查   | **不能**   |
| `knowledge` | 知识点所属册次反查 | **不能**   |
| `free`      | 无（默认「不限」） | **能**     |

理由：题目/知识点场景的学科是**内容本身的属性**，让用户改会出现「问着英语题却标成数学」
的错上下文；自由问答没有内容可依，学科本来就未知，预填反而是编造。

- 「我的 → AI 辅导」只传 `grade`，不再传 `subjectName`。
- AI 页在 `scene === 'free'` 时异步拉 `subjectResolver.listSubjectNames()`，
  渲染「不限 / 英语 / 数学」chip，默认选中「不限」；拉不到就整行不显示。
  这是本页唯一的云调用，且失败不影响自由问答本身。
- 自由问答的上下文条标题改为「自由问答」而不是空着，也不冒充某学科。

### 7.5 后果

**正面**：「答错 → 问 AI」闭环；AI 侧拿到的上下文从 3 项（知识点/学科/年级）
变为 9 项（+题干/选项/学生答案/正确答案/学段/提示历史）；三级提示有 20 个单测守着。

**待办**：

- 测试结果页的「AI 学习建议」入口 —— 需要第 4 个场景（`sceneOf` 目前只有 3 种），未做。
- 会话历史不落库（刷新即失）——V1 有意如此，避免动集合结构；如需保留要新增集合（须先确认）。
- 多轮上下文窗口：目前每次请求只带 `AiTutorContext` + `hintHistory`，不带历史对话，
  AI 记不住上一轮的完整问答。

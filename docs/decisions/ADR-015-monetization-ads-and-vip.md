## 3. 决策

### 3.1 权益模型

```
membership: { tier: 'free' | 'vip', expireAt: Date | null, source: 'purchase' | 'gift' }
adUnlocks:  { [unlockKey]: expireAt }   // 按次解锁，unlockKey 见下
```

- **会员**：`tier === 'vip' && expireAt > now` → 全部功能免广告。
- **按次解锁**（Owner 选定）：解锁键 = `test_result:{chapterId}:{timestamp}` 一类**带业务标识**的键，
  不是全局「解锁测试结果」。理由：Owner 要的是「**本次**结果」，解锁一次不能顺带把别章的结果也开了。
- 解锁记录**只写云端**（云函数收口），客户端不得直写 users —— 否则改本地就能白嫖。

### 3.2 门禁点（Gate）

| 功能               | 免费用户               | 会员   |
| ------------------ | ---------------------- | ------ |
| AI 辅导（整页）    | 需按次解锁（观看视频） | 直接进 |
| 测试结果（本次）   | 需按次解锁（观看视频） | 直接看 |
| 其余学习/复习/游戏 | **永远免费，不设门禁** | 同左   |

> 红线：**学习主链路不加广告**。学习、复习、单词卡、小游戏一律免费——
> 变现压在「AI 讲解」与「测试分析」这两块增值内容上，不能挡住孩子背书。

### 3.3 广告与降级

- 用**激励视频** `wx.createRewardedVideoAd`（不是插屏/横幅）。
- **文案统一「观看视频」**，不出现「看广告」（Owner 既有措辞要求，全量一致）。
- **广告不可用必须放行**：无广告位、加载失败、看完回调丢失 → 直接解锁并提示，
  **不许把用户卡在门槛外**。可用性 > 转化率。
- 每天解锁次数做云侧限频（防刷），但不向用户展示"还剩几次"这类压迫性文案。

### 3.4 支付（会员）

- 走**虚拟支付道具直购**（`mode: 'short_series_goods'`）：单次会员购买，链路短、用户理解成本低。
- 服务端：生成订单号 → 组装 `signData` → 算 `paySig`/`signature` → 前端调 API →
  **发货回调 + 主动查单**确认终态 → 落 `membership`。
- AppKey 只存云函数环境变量，**不进代码、不进 git**。

## 4. 前置条件（Owner 在 MP 后台做，我无法代做）

1. 开通**虚拟支付**（支付与交易 → 虚拟支付），拿到 `OfferID` / 现网 `AppKey` / 沙箱 `AppKey`
2. 创建**道具**（如 `vip_month`、`vip_year`），记录 `productId` 与价格（**分**），发布到现网
3. iOS 要能买：配置**小程序简称** + 开通**苹果 IAP 支付**
4. 开通**流量主**拿激励视频广告位（通常有累计 UV 门槛，以后台提示为准）

## 5. 分阶段实施

| 阶段 | 内容                                                                                                  | 依赖             |
| ---- | ----------------------------------------------------------------------------------------------------- | ---------------- |
| P0   | 权益服务 `entitlementService` + 门禁 UI + 激励视频解锁 + 广告不可用降级放行；会员入口显示「敬请期待」 | **无，立即可做** |

### 5.1 P0 落地记录（2026-09-14）

| 文件                                    | 作用                                                               |
| --------------------------------------- | ------------------------------------------------------------------ |
| `core/entitlement.ts`                   | 权益数据模型：会员态 + `unlockKey → 到期时间`，两者分开存          |
| `config/entitlements.ts`                | 门禁点清单 + `unlockKeyOf` / `dayKey` / `expireAtOf` / `featureOf` |
| `config/ads.ts`                         | 激励视频广告位（**当前留空 → 全站门禁自动放行**）                  |
| `repositories/entitlementRepository.ts` | `user_entitlements` 集合读写                                       |
| `services/entitlementService.ts`        | `decide` 判定 + `grantUnlock` 记一次解锁                           |
| `services/rewardedAdService.ts`         | 激励视频封装：`watch()` 只回 outcome，不抛异常                     |
| `utils/entitlementGate.ts`              | 「判定 → 界面状态」纯映射（可单测）                                |
| `components/entitlement-gate/`          | 门禁组件：放行渲染 slot，拦住渲染解锁卡                            |

落地要点：

- **解锁键 = `功能:业务标识:本地日期`**。日期进 key，TTL 就不需要清数据；
  业务标识进 key，「本次结果」才不会被「解锁整类」顺带打开。
- **组件用 slot 承载被保护内容**：AI 页把对话区/快捷栏/输入区整体包住，
  测试结果页只包住成绩卡（导航按钮始终可见，不挡出口）。
- **降级链路上每一环都放行**：集合没建 → 放行；未登录 → 放行；`feature` 名写错 → 放行；
  广告位没配 → 放行；加载失败 / 回调丢失 → 放行并提示。只有「中途退出」不给解锁。
- **广告位留空时整套门禁等于不存在**，可安全上线，等流量主开通后填 id 即生效。

⚠️ 与 §3.1 的一处偏差（已权衡，待 P1 加固）：

- 原方案写「解锁记录只写云端（云函数收口）」。P0 未新增云函数，解锁记录由**客户端直写**
  `user_entitlements`（权限「仅创建者可读写」，用户只能改自己的记录），不是写 `users`。
- 后果可控：伪造解锁最多白嫖「当天的一段 AI 讲解 / 一次测试分析」，
  而正常路径本来也就是看一段视频；真正涉及钱的 `membership` 仍**只在 P1 由云函数写入**。
- P1 补两件事：① 会员态写入收口到云函数；② 解锁写入加云侧限频（§3.3 已有此条）。

## 6. 风险

| 风险          | 说明                                                             |
| ------------- | ---------------------------------------------------------------- |
| 费率/规则变动 | 2026 年虚拟支付规则仍在频繁更新，实现前须复核官方文档            |
| 价格一致性    | iOS 与安卓价格必须一致，禁止渠道差异定价                         |
| 回调安全      | 发货推送须按订单号幂等，返回 0 才算成功；只信前端 success 会漏单 |
| 退款          | 虚拟商品退款规则（未消费可原路退）需在购买页写明                 |
| 未成年人      | 教育类面向学生，会员购买入口不做强引导、不做倒计时压迫           |

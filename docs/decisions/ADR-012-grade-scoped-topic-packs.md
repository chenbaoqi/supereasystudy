# ADR-012：跨年级专题包按年级过滤，空分类隐藏

- 日期：2026-09-13
- 状态：已实施（待重新导入云数据后生效）
- 关联：ADR-011（教材为顶层选择项）、RULES §7（不得删除已有字段）

## 背景与问题

用户选了「数学 → 人教版 → 一年级上册」后，学习页的**公式**分区仍然列出三个分类：
**数与运算 / 图形与几何 / 统计与概率**。一年级根本没有后两个分类的内容。

用户原话：

> 我选择小学一年级，哪里来的图形几何，统计概率呢。我的意思是教材没有的内容，分类，就隐藏起来

## 根因（不是渲染 bug，是数据缺维度）

`data.js` 里数学有两条学习路径：

| 学习路径 | 教材         | 册次                             | 说明                                       |
| -------- | ------------ | -------------------------------- | ------------------------------------------ |
| 知识点   | 人教版       | 18 册（一年级上册 … 九年级下册） | 按册次组织，天然限定年级                   |
| 公式     | 小学公式专题 | 全册                             | **整学段词典**：1–6 年级 34 条公式混在一起 |
| 公式     | 初中公式专题 | 全册                             | **整学段词典**：7–9 年级 40 条公式混在一起 |

专题包只有一个「全册」册次，**没有年级维度**，所以无论当前册次是几年级，
学习页都把整包 34/40 条公式全列出来。

### 为什么不能只按「章节标题」过滤

一年级上册确实有「认识立体图形」这个章节，但专题包里的「图形与几何」章节
装的是**平行四边形面积（五年级）**、**圆锥体积（六年级）**。
按标题匹配会把五年级的内容塞给一年级 —— 所以过滤必须下沉到**知识点级**。

## 决策

**给知识点加 `grade` 字段，读取时按「当前年级」过滤；被过滤空的章节/分类整体隐藏。**

### 过滤规则（三条，缺一不可）

1. 知识点**未标** `grade`（undefined）→ 不限年级，恒显示。
   保证现有 1500+ 条旧数据零回归，常规册次里的知识点不用补标注。
2. 知识点**标了** `grade` → 仅当 `grade <= 当前年级` 才显示。
   **累积式**，不是「只给本年级新增」：六年级要能看到一年级学过的公式（复习场景），
   但一年级绝不能看到六年级的（超纲）。
3. **当前年级解析不出来** → 一律不过滤（原样返回）。
   宁可多显示，也不能因为册次名解析失败把内容整片藏掉。

### 年级从哪来

从**用户当前册次偏好**（`preferences.semesterName` / `preferencesBySubject[subjectId].semesterName`）
解析，不是从章节所属册次。因为专题册次叫「全册」，从它反推不出年级，
只能取用户真正在读的那一册（`utils/stage.gradeOfSemester`）。

`scripts/annotate_math_formula_grades.js` 是唯一标注源，**幂等**（已含 grade 的条目跳过），
改数据后重跑即可。取「该公式在人教版**正式出现并要求掌握**」的年级。

## 改动清单

**数据**

- `cloud/functions/resetAndImport/data.js`：74 条公式加 `grade` 字段（脚本写入，未手写）
- 同文件顺带修正 2 处答案与自身讲解矛盾的题目：
  - 加法交换律「37+58+63 最简便」：原答案 `58+63` → 改 `37+63`（example 写的是先算 37+63=100）
  - 一元二次方程「x²−5x+6=0 的根」：原答案 `x=−2 或 −3` → 改 `x=2 或 3`（example 写的是 (5±1)/2）
- `cloud/functions/resetAndImport/index.js`：
  - knowledge 可变字段加 `grade`
  - upsert 决策新增「源未提供该字段则不写入」保护，避免把已有值写成 `undefined`
    （云函数 update 传 undefined 会报错，且符合 §7 不得删除已有字段）

**类型 / 服务**

- `core/knowledge.ts`：新增可选 `grade?: number`（缺省 = 不限年级）
- `services/gradeScope.ts`（新）：`withinGrade()` 纯过滤 + `createGradeScope()` 解析当前年级
- 接入年级过滤的调用点（全部为**末尾可选参数**，不传 = 旧行为）：
  - `chapterService.buildChapterItems(userId, semesterId, grade)` —— 分类显隐（本 ADR 的核心修复）
  - `learningService.startLearning / continueLearning / finishLearning / getCurrentKnowledge`
  - `reviewService.createReviewTasksForChapter`
  - `listenFindService / memoryGameService / spaceShooterService / speedChoiceService / grammarGameService` 的 `startGame`
  - 页面：`study` / `study-detail` / `test` / `chapter` / `practice` / 5 个游戏页

## 被否决的方案

| 方案                                    | 否决原因                                                                                             |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 按章节标题匹配年级                      | 章节内混着多年级内容（一年级「认识图形」章节里塞着五年级的平行四边形面积），过滤不住                 |
| 把专题包拆成 6 个年级册次（数据里复制） | 内容重复难维护；且同一公式在不同册次 `_id` 不同 → 学习进度跨年级断裂（三年级学的公式四年级又变新卡） |
| 只补数据不改代码 / 只改代码不补数据     | 二者必须配套：`grade` 字段是数据的维度，过滤逻辑是消费方，缺任一都修不掉                             |

## 上线必须做的事

云数据变更，**不会随前端热更新生效**：

1. 重新上传并部署 `resetAndImport` 云函数
2. 调用一次 `resetAndImport`（upsert 模式，保留用户数据；本次是新增字段，不会删任何已有记录）
3. 验证：切到「一年级上册」→ 公式分区应完全消失；切到「六年级下册」→ 三个分类全开

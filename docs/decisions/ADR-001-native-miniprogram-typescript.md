# ADR-001：小程序技术框架 —— 微信原生 + TypeScript

- 状态：**已决策**（2026-07-19，Owner 拍板）
- 决策人：Owner

## 背景

产品 V1 平台为微信小程序（Specification 第二章）。候选框架：

| 方案             | 优势                             | 风险                                  |
| ---------------- | -------------------------------- | ------------------------------------- |
| A. Taro + React  | 多端编译、React 生态             | 构建链复杂；官方新能力跟进滞后        |
| B. 微信原生 + TS | 最稳定、官方能力零延迟、性能最好 | 锁定微信单端                          |
| C. uni-app + Vue | 多端、国内生态大                 | 抽象层同 Taro；Vue 生态与团队偏好不符 |

## 决策

采用 **B：微信原生小程序 + TypeScript**（开发者工具内置 TS 编译，`useCompilerPlugins: ["typescript"]`）。

## 理由

- V1 唯一端是微信小程序，原生方案稳定性与能力跟进速度最优
- 多端诉求（V3 Learning OS）通过 `core/` 领域抽象的**框架无关**来对冲，而非框架层多端编译
- 依赖最少 = 三年维护期内工具链腐化风险最低

## 后果

- 未来若需 H5/App 端，需重写视图层；`core/`、`services/` 的设计必须保持不含 wx API（`utils/` 除外），降低重写成本

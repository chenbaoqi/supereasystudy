## 数学题 CSV 与可视化字段（visual）

`merge_math_quiz.mjs` 读三个 CSV，按**知识点名（`knowledge.word`）**挂载到 `data.js`：

| CSV                                  | 挂载对象                | 额外列                      |
| ------------------------------------ | ----------------------- | --------------------------- |
| `assets/math-formula-quiz-draft.csv` | 公式专题第一批（27 点） | —                           |
| `assets/math-concept-quiz-draft.csv` | 教材知识点              | `chapter`、`visual`、`note` |
| `assets/math-formula-quiz-g2.csv`    | 公式专题第二批（47 点） | `path`（**必填**、见下）    |

列：`point,chapter,stem,optionA,optionB,optionC,optionD,answer,visual,note`
（`chapter` 可选，用于同名知识点消歧；`point` 全局唯一时可省略。）

⚠️ **第二批为什么单独一个文件、且必须写 `path=公式`**：47 个点里有 9 个
（`平均数`、`平行四边形面积`、`乘方`、`科学记数法`、`反比例函数`、`二次函数`、
`勾股定理逆定理`、`平行线性质`、`方差`）与「知识点」路径**同名**。不写 `path` 时匹配阶段
会把同一批题挂到两个路径的同名点上 —— 而挂载是**整体替换**不是追加，
「知识点」那边原本好好的题会被公式题覆盖掉。

两个连带的坑：

- 不能在老 CSV 里补 `path` 列：老文件的行仍是 8/10 列，加列会让它们因「字段数不符」被整行跳过。
- 挂载是**替换**：给已经有点题的知识点加题时，必须把旧题一起抄进 CSV，否则旧题丢失。

⚠️ **所有字段禁止出现半角逗号** —— CSV 是无引号的简单切分，题面停顿请用全角「，」。

### visual 字段格式

```
<类型>|<键>=<值>|<键>=<值>
```

分隔符：`|` 分段、`;` 分多个点、`~` 分点内字段。刻意不含半角逗号。

| 类型               | 必填                      | 示例                                                     |
| ------------------ | ------------------------- | -------------------------------------------------------- |
| `number-line`      | `min` `max`               | `number-line\|min=-5\|max=5\|value=-3`                   |
| `fraction`         | `numerator` `denominator` | `fraction\|numerator=3\|denominator=4\|compare=2/3`      |
| `coordinate-plane` | 无（默认 −5..5）          | `coordinate-plane\|points=3~-2~P;5~3~A'\|xMin=0\|xMax=6` |

- 数值的负号必须用**半角 `-`**，全角 `−` 会被 `Number()` 转成 NaN 并丢弃该图。
- 缺必填属性 / 类型拼错 → 该图被丢弃并打印告警，**题目本身照常入库**
  （教学场景里「题能答」优先于「题有图」）。
- 渲染契约在 `miniprogram/core/visual.ts`，本脚本的 `REQUIRED_PROPS` 与它保持一致。

### relations.js 校验

`merge_math_quiz.mjs` 每次运行都会校验 `cloud/functions/resetAndImport/relations.js`
里的每个「章节/知识点名」能在数据中**唯一定位**，定位不了就直接 `exit 1`。
原因：知识图谱关系靠名字在导入时解析成 `_id`，改名会让关系静默失效。

## 数学知识点讲解（`merge_math_content.mjs`）

学习详情页的「数学 · 知识点」一度看着只有标题，根因是**数据稀疏而不是渲染 bug**：
教材知识点由 CSV 批量生成时只填了 `meaning`（约 11 字）和 `example`（约 9 字），
**从没写过 `explanation`**；对比英语语法点平均 109 字的讲解，差距是全链路显示的。

本脚本把人工撰写的讲解挂回 `data.js`。当前内容源：`assets/math-concept-content-draft.csv`。

列：`word,chapter,explanation,example`

- `word` 必填，`explanation` 必填，`example` 可留空（留空表示不动原有例句）
- ⚠️ **`chapter` 是定向开关，不是注释**：写了就只喂给那一章；不写则喂给所有同名知识点。
  「平移」在三年级下册 / 五年级上册 / 七年级下册都有，「实际问题」在九年级三册都有，
  「平行线性质」在教材知识点与公式专题里都有 —— 靠 `chapter` 隔离才能避免
  **把七年级的讲解串写到三年级**。某行与当前章不匹配属于正常跳过，不报错。
- ⚠️ 同样适用「字段里禁止半角逗号」的规矩（讲解里写 `x = 3, y = 2` 会把一行切成 5 个字段）
- ⚠️ **字段里也禁止半角引号**：这些 CSV 是无引号切分，给 example 加 `"` 想「保护」它，
  引号会变成内容的一部分原样写进数据库，学生看到的是带着一对引号的文字。
  这个坑已经踩过两次（2026-09-15 一次误加 378 个），所以写了 `check_content_csv.mjs` 来拦。

改完 CSV 后先跑校验再合并：

```bash
node scripts/check_content_csv.mjs   # 退出码 0 才继续
node scripts/merge_math_content.mjs
```

- 讲解短于 40 字仅告警（提纲 ≠ 讲解）；**定位不到唯一知识点或歧义 → `exit 1` 且不落盘**

## 习题 CSV 校验（check_quiz_csv.mjs）

题目比讲解更容易写废，而且**失败是静默的**：`merge_math_quiz.mjs` 对概念知识点定位不到时
只是跳过（只有公式点才会报 missing），白写的题不会有任何提示。所以合并前先跑：

```bash
node scripts/check_quiz_csv.mjs   # 默认校验 concept + formula 两个 CSV，可传文件路径
node scripts/merge_math_quiz.mjs
```

检查项：字段数、显示列的半角引号（`visual` 里的 `A'` 是合法坐标标签，不查）、`answer` 是否
A/B/C/D、四个选项是否重复、`visual` 类型与**负号必须半角**、`point+chapter` 能否唯一定位、
每点题数（建议 2~3）、答案是否过度集中在 A。

两个已知的非错误提示，别当 bug 修：

- **公式 CSV 未填 chapter 时命中 2 处**（如「三角形面积」在五年级上册概念路径 + 公式专题各一条）
  → 题目会**同时挂到两处**，这是现状预期行为，脚本只打 `ℹ️`。
- **「有题目但路径/章节对不上」**（合并器输出）→ 多半是同名的**其它册次**知识点没吃到这题。
  例如给七上的「近似数」出题，四上的同名点也报这一条，属正常；确认目标册次覆盖即可。
- ⚠️ 一轮挂载会**整体替换**该知识点的 `quiz`（`knowledge.quiz = 命中行.map(...)`），
  所以已经手工配好题的知识点（如「数轴」）**别再往 CSV 里加同名行**，除非把旧题一起抄回来。

### ⚠️ 打散答案必须用「行号区间」限定范围，不能用章节名

写新题时正确选项习惯写在 A 位，写完要打散到 A/B/C/D。打散脚本**按章节名筛行是错的** ——
「三角形」「圆」「数据的收集与整理」这类章节名在**小学和初中同名**，用章节名会把初中旧题
一起选中**二次打散**，把之前已经正确的答案字母打乱（正确选项仍在 A 位，字母却指向别的选项）。
2026-09-15 实测误伤 20 行，靠逐行核对才修回来。

正确做法：

```js
const FROM = 534; // 本批新增行的起始行号（1-based，含表头）
if (idx + 1 < FROM) return line; // 只动新增的行
```

万一已经误伤：正确选项一定还在 **A 位**（打散是 swap(0, t)），所以把 `answer` 改回 `A`
再重新分布即可，不需要猜。

`explanation` 已在 `resetAndImport/index.js` 的 `mutableFields` 白名单里，
**内容改完重新部署云函数即可生效**，不用动云函数代码。

> ℹ️ **建议攒够一批再部署一次**。导入是幂等的：`upsertCollection` 会逐字段比对，
> 只把真正变化的字段写进 patch。所以「写一批部署一次」与「全部写完再部署」最终库状态完全一致。
> 而每轮部署都要走「上传云函数 → 云端测试 → 等返回」这一整套，
> 没必要为了几行 CSV 文案反复走 —— **一次部署把差异全拍平最划算**。

## 规则

- 脚本必须可用 `node scripts/xxx.mjs` 直接运行，不依赖全局安装
- 脚本只做工程自动化，**禁止包含产品业务逻辑**
- `data.js` 是 **CommonJS 模块且被 prettier 格式化过**（单引号、键不带引号），
  脚本里只能 `require` 它，**不能** `JSON.parse`（会直接抛错）
